# P2-0 조달 데이터 가용성 spike

측정일: 2026-09-02

## 결론

나라장터 데이터는 공공 발주 신호를 보강하기에는 필드와 갱신 주기가 충분하지만, 현재 프로젝트에는
승인된 서비스 키가 없고 민간 제조사 발주를 포괄하지도 않는다. 따라서 이번 P2-2에서는 조달 커넥터를
추가하지 않는다. 기사 입력만으로 `dealSignal`을 판정할 수 없을 때는 0점이 아니라 unavailable로 두고,
나머지 가용 축의 가중치를 재정규화한다.

## 접근성

- 공식 [나라장터 입찰공고정보서비스](https://www.data.go.kr/data/15129394/openapi.do)는 무료이며
  개발·운영 활용신청이 자동승인이다. 개발계정 기본 트래픽은 일 1,000회다.
- 2026-09-02에 용역 입찰공고 검색 오퍼레이션
  `GET /1230000/ad/BidPublicInfoService/getBidPblancListInfoServcPPSSrch`를 인증키 없이 호출했다.
  HTTP 401과 `SERVICE_KEY_IS_NULL`(reason 20)을 확인했다. 즉 공개 명세는 바로 읽을 수 있지만 실제 표본
  조회에는 발급·승인된 키가 필요하다.
- 저장소 규칙에 따라 실제 `.env`나 자격증명 파일은 열지 않았다.

판정: **프로젝트 런타임 접근성 미달**. 키가 생기기 전 운영 커넥터를 만들지 않는다.

## 필드와 갱신 주기

공식 명세는 물품·용역·공사·외자별 목록/상세, 기초금액, 제한, 변경 이력을 JSON/XML로 제공하고
갱신 주기를 실시간으로 명시한다. P2의 사업 신호에 필요한 최소 필드는 다음과 같이 대응된다.

| 목적 | 필드 | 판정 |
|---|---|---|
| 공고 식별·정정 추적 | `bidNtceNo`, `bidNtceOrd`, 변경 이력 | 충족 |
| 사업명·키워드 | `bidNtceNm` | 충족 |
| 발주·수요기관 | `ntceInsttNm`, `dminsttNm` | 충족 |
| 예산·추정가격 | `asignBdgtAmt`, `presmptPrce` 계열 | 충족, 공고별 null 허용 필요 |
| 공고·입찰·마감 시각 | `bidNtceDt`, `bidBeginDt`, `bidClseDt` | 충족 |
| 원문 추적 | `bidNtceDtlUrl`, 공고 문서 URL | 충족 |
| 갱신 주기 | 실시간 | 충족 |

[발주계획현황서비스](https://www.data.go.kr/data/15129462/openapi.do)는 조달대상·예산액·예정시기·방법을
제공하지만, 공식 설명도 발주계획 없이 사전규격·입찰·계약이 존재할 수 있다고 밝힌다. 계획 데이터만으로
커버리지를 보장할 수 없다.

## 표본 커버리지

회사 구축 사례에서 가져온 8개 표본 키워드(OEE, SPC, 예지보전, 품질 최적화, 공정 최적화,
자율제조, 스마트팩토리, 제조 데이터 플랫폼)는 공고명 검색 필드로 질의 가능한 형태다. 그러나 승인된
키가 없어 8개 모두 실데이터 hit/recall을 재현하지 못했다(**검증 0/8**). 또한 나라장터의 범위는
공공기관·지자체 중심이라 핵심 고객군인 민간 반도체·디스플레이·이차전지 제조사의 직접 발주는 구조적으로
빠질 수 있다.

판정: **커버리지 기준 미달**. 검색 가능성과 실제 표본 커버리지를 같은 것으로 간주하지 않는다.

## P2-2 반영 계약

1. `dealSignal.score = null`은 입력 자료로 판정 불가함을 뜻한다. `score = 0`과 구분한다.
2. 축 점수가 null이면 근거 문장 배열은 비어 있어야 한다.
3. 총점은 가용 축만 `0.35 / 0.30 / 0.20 / 0.15` 가중치를 재정규화해 계산한다.
4. 기사 자체에 수주·입찰·예산 집행이 직접 적혀 있으면 조달 커넥터가 없어도 `dealSignal`을 채울 수 있다.
5. 본 커넥터는 서비스 키를 안전하게 공급하고 8개 표본의 재현 가능한 coverage 측정을 통과한 뒤 별도
   이슈로 연다.
