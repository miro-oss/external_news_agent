# 서로 다른 업체의 발표 과병합 회귀 검증 — #163

2026-09-04 · [이슈 #163](https://github.com/miro-oss/external_news_agent/issues/163) · 로컬 전용

사용자가 원본 기사 **3797(한화세미텍) / 3771(디엠에스)**를 **다른 사건**으로 확인했다.
같은 전시회에서 다른 업체가 발표한 기사인데 제목 Jaccard가 0.50이라 기존 규칙이 병합했다.
이 판정은 해당 쌍의 사건 경계 확인이며, #162 전체 기준 라벨을 사람이 검수했다는 뜻은 아니다.

## 변경

- 제목에 명시된 조직 집합이 서로 겹치지 않으면 새 규칙 간선의 병합을 거절한다.
  요약·본문의 배경 조직 언급은 제목의 충돌을 해소하지 않는다.
- 컴포넌트마다 개별 제목의 조직 집합을 보존한다. 조직 미상 기사나 복수 조직 기사를
  경유하더라도 서로 다른 업체 발표를 전이적으로 연결할 수 없다. 기사 ID 순으로 간선을
  처리해 입력 목록 순서가 달라도 같은 결과를 만든다.
- 한화세미텍·디엠에스·한미반도체의 한/영 별칭은 충돌 판정에 추가했다.
  이 별칭만으로 기존 긍정 조직/엔티티 병합 근거를 늘리지는 않는다.
- Python 평가 재생에도 같은 충돌 규칙과 순서를 적용하고 Java exporter에 제목 조직과
  규칙 버전을 기록한다. 새 버전의 조직 필드가 누락되거나 형식이 잘못되면 평가 전에 거절한다.
  실제 Java 결과도 `configuredIssueRepresentativeId`로 확인할 수 있다.
- 버전 없는 기존 export는 경고를 남기고, 결과의 `titleOrganizationGuard`에 메타데이터
  완전성·프로파일이 있는 기사 수·평가 구현 버전을 기록한다. 없는 프로파일은 충돌을 판정하지
  못하며, 알 수 없는 규칙 버전은 평가 전에 거절한다. 세 exporter는 실제 클러스터러 인스턴스의
  공통 제목 조직 추출 메서드를 사용해 전처리와 추출기 설정이 갈라지지 않게 한다.

## 검증

실제 제목을 사용하는 회귀 테스트와 별칭·조직 미상/복수 조직을 통한 전이 경로·같은 업체·공동 발표·
요약 우회·기존 멤버십 보존 테스트를 추가했다. 기존 클러스터 테스트도 함께 통과했다.
Java 클러스터 테스트 91개와 별도 실제 입력 재생 1개, Python 검증 도구 테스트 66개가 통과했다.
환경 변수가 필요한 기존 v2 원문 재생 1개는 실행하지 않았다. Ruff와 diff 공백 검사도 통과했다.

PR 리뷰 반영 후에는 Java 클러스터 테스트 94개가 통과했고, 외부 원문 경로가 필요한 재생
2개는 생략됐다. Python 검증 도구 테스트 72개와 Ruff·diff 공백 검사가 통과했다.

#162 원문 160건의 제목·요약·본문을 그대로 읽어 현재 기본 설정으로 Java 클러스터를 재실행했다.
봉인 자료 옆의 별도 `cluster-regression-163` 디렉터리에 결과를 보관한다.

새 독립 정확도 통과를 선언하거나 기존 선택 임계값을 재조정하지 않았다.

## 적용 범위와 남은 확인

원격 배포는 필요 없다. 수정된 백엔드를 로컬에서 재시작하면 새 규칙 간선에 적용된다.
기존 저장 이슈·동일 본문 그룹의 멤버십은 유지하므로 과거에 잘못 묶인 이슈가 자동으로 갈라지지는 않는다.
이 수정은 기존 DB 자료를 삭제하거나 재분류하지 않는다.

이미 `{한화세미텍}`과 `{디엠에스}` 기사가 함께 저장된 이슈/본문 그룹에는, 제목이 기존
한화 기사와 완전히 같아도 새 `{한화세미텍}` 후속 기사를 붙이지 않고 별도 이슈로 남긴다.
저장 멤버십은 유지하지만 과거 과병합의 확대는 막는 보수적 정책이다. Java에서 저장 이슈와
본문 그룹 각각의 세 기사 입력을 여섯 순서로 재생했고, Python의 본문 그룹 회귀도 같은
거절 동작을 검증한다. 모든 새 기사를 막는 것은 아니다. 조직 미상이나 기존의 모든 프로파일과
겹치는 복수 조직 기사는 기존 긍정 조건이 맞으면 합류할 수 있고, 양쪽 구현에 이 대조 회귀도 있다.
강제 결합된 그룹의 프로파일을
비우거나 한 프로파일만 겹쳐도 허용하면 기존 과병합 및 복수 조직을 통한 전이 병합이 다시
커지므로 이 PR에서 완화하지 않는다. 기존 이슈를 바로잡으려면 별도 승인된 재분류가 필요하다.

TF-IDF 두 비교군은 의도적으로 제목 조직 충돌 가드를 사용하지 않는다. 결과에
`usesTitleOrganizationGuard: false`를 기록한다. 규칙과 비교군은 사용하는 신호가 다르므로
점수 차이를 임계값 규칙 자체의 개선이나 가드 단독 효과로 해석하지 않는다.

#162 pack의 봉인과 당시 결과는 유효하게 보존된다. 다만 `cluster_sweep.py`와
`cluster_independent.py` 코드 해시가 달라져 이 수정본으로 기존 pack을 재평가하면
`Sealed protocol or evaluation code changed`로 거절된다. 당시 수치의 재현은 봉인 당시
커밋 `6fa8b9ccdc12e8857fdaa48763664b81eda41277`의 평가 코드와 원본 pack으로 수행하고,
수정 규칙의 독립 정확도는 새 표본·새 pack으로 평가한다. 기존 봉인 해시를 새 코드에 맞춰
고치거나 기존 holdout을 새 성능 증거로 재사용하지 않는다.

사전에 없는 업체나 제목에 업체명이 없는 경우는 조직 충돌을 확정할 수 없다.
실제 공동 사건을 각각 다른 당사자 이름만으로 보도한 경우에는 보수적인 충돌 규칙이 분리할 수 있다.
같은 업체라는 사실만으로 같은 사건임을 보장하지도 않는다.
정식 정확도 판단은 수정본의 로컬 실행에서 얻은 새 표본을 예측과 분리해 라벨링한 뒤 수행한다.
본문 정보가 부족한 사례는 불확실성을 유지한다.

## 재현

```sh
cd BE

```

```sh
cd agent
.venv/bin/python -m pytest tests/test_cluster_sweep.py tests/test_cluster_snapshot.py tests/test_cluster_independent.py -q
```

실제 원문 재생은 `IssueClustererIndependentExportTest`의 `CLUSTERS_INDEPENDENT_GOLDEN`에
기존 golden 파일, `CLUSTERS_INDEPENDENT_OUTPUT`에 **새 회귀 디렉터리** 경로를 전달한다.
이 경우 기존 pack의 `cluster_independent evaluate`를 다시 실행하지 않는다.
